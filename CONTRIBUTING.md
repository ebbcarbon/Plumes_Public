# Contributing

The rules below are the ones that bite; the full versions live in
[`notes/PLAN.md`](notes/PLAN.md) §8 ("Working rules"). Setup is in the README; toolchain
detail in [`notes/ENVIRONMENT.md`](notes/ENVIRONMENT.md).

## Running the tests

```powershell
.venv\Scripts\python.exe -m pytest -n auto --dist loadfile   # everything, ~4 min cold, less with a warm outcome cache
.venv\Scripts\python.exe -m pytest -m "not slow"             # the fast lane
.venv\Scripts\plumes2 validate                               # the ledger, re-derived
```

- ⚠️ **`-n auto --dist loadfile`, never bare `-n auto`.** Per-file distribution preserves the
  shared, module-scoped fixtures the suite is built on; bare `-n auto` scatters them and one
  2.5 s module becomes a 233 s one.
- Measured outcomes are cached (gitignored `.plumes2_outcome_cache.json`), keyed on a digest
  of `src/plumes2` plus the reference data — any change to either discards it whole, so the
  first run after a model change is the slow one.
- Lint and types: `ruff check src tests` and `mypy` (config in `pyproject.toml`).
- The PHREEQC engine is an extra (`pip install -e ".[dev,pitzer]"`, as CI does); without it
  `tests/test_pitzer.py` skips as a module and ledger rows 287–289 report an error in
  `plumes2 validate` rather than a pass.

## What is never edited

- **`upstream/`** — the verbatim PLUMES2.0 snapshot. Read-only, always.
- **Exe-produced data** — every `.dat`/`.csv`/`.prj` in `reference_cases/`. The READMEs
  beside them are ours and editable; the data is evidence.
- **`notes/PLAN_HISTORY.md`** — frozen. Search it; never append to it. New narrative goes in
  a case README, a study README, or a ledger row.

## Claims need a home

This project's one non-negotiable habit: a number that gets published somewhere must be
*re-derivable*, not typed.

- A new **finding** gets a row in [`notes/LEDGER.md`](notes/LEDGER.md) (numbers never reused,
  retractions struck through in place, tolerances from what the reference can resolve) **and**
  a `Target` in `src/plumes2/validation.py` that re-derives it. The row, its bucket heading
  count, the identity set and row-count pin in `tests/test_validation.py`, and the `Target`
  all move together.
- Coverage figures quoted in prose (README, PLAN, PORTING_THE_PHYSICS) are test-checked
  against the derived counts — update them all together or the suite fails.
- A new **exe experiment** is generated by `plumes2.experiments` into
  `reference_cases/pending/` with its predictions registered *before* the run. A miss is
  recorded as a miss.

## Conventions

- Results are dataframes; every physics module is callable alone; no global state; SI inside,
  units only at the boundary.
- Docstrings carry the findings, not just the signatures — where the exe departs from its
  manual, the docstring says which reading the traces chose, and by how much.
- Exe defects are **corrected by default, reproduced on request** via `reproduce_*` flags.
- No `PR_BODY.md` or similar throwaway files committed to the repo.
- Python ≥ 3.13; line length 100; `ruff` and `mypy` clean before a PR.
