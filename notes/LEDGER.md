# Validation ledger

Every numbered finding about the exe, what it was measured against, and whether a target in
`plumes2.validation` runs it. **316 rows**, of which **all 191 countable ones** are
executable — the ledger has been complete since 2026-08-25, when row 258c closed and row 278
was added; rows 280/280b (2026-08-26, the far-field law selector) and 281–283 (2026-09-01,
the flag-decode suite, case51/case52) arrived executable.

⚠️ **Complete is not finished.** Three rows still record open *problems* rather than open
measurements: **157b/186** (merging is 1–7 % wrong post-merge past `d/L` 3, the port's largest
known residual), **195** (`Ω_brucite` has no parity target by construction — the exe cannot
report it), and **187** (whether the `.prj` carries a build stamp; no input exists). Executable
means every countable claim re-derives on demand, not that nothing is left to learn.

**This file is the denominator.** `test_the_ledger_denominator_matches_the_ledger` recomputes the
per-phase counts from it on every build, so the coverage table in `PLAN.md` cannot drift from what
is written here, and implementing a target cannot shrink the denominator — the rule reads the
ledger, never the registry.

## How to read it

⚠️ **Rows are grouped by phase, then by resolution, and sorted by number within each.** Row numbers
are historical and are **never renumbered**: a row's number is how every commit message, case
README, module docstring and registry entry refers to it, so the order on the page is presentation
and the number is identity. The sequence has gaps — 7, 13, 142, 232, 233, 234, 236 and 249 were
consolidated into the rows that superseded them (6, 12, 136, 225 and 251) — and the numbers are not
reused.

⚠️ **A struck-through row is kept, not deleted.** A retraction that leaves no trace is how a project
forgets what it already got wrong, and this one has got the same class of thing wrong more than
once — the Froude reading of the merging lag, port depth after it, and a coverage numerator that
counted targets against a denominator of rows. Each failure is recorded where it happened.

### The three buckets

| | |
|---|---|
| ✅ **Measured** | a target in `plumes2.validation` runs it on every build |
| ⏳ **Open** | recorded, and either the measurement is still to be written or the data to settle it does not exist |
| ⊘ **Not executable** | retired with a reason, and excluded from the denominator |

⊘ is an admission rather than a dismissal: it says *this claim is true and worth keeping, and no
measurement of ours can add to it*. Exactly four reasons are allowed and every marked row names
one — `subsumed` (which must name the covering row), `documentary`, `downgraded`, or `no input`
(which must say which input is missing).

⚠️ **The tag is the guard against this becoming a way to make coverage look good.** A test asserts
every marked row carries one of the four, and the derived denominator drops them — so marking a row
*moves the coverage figure* rather than quietly improving it.
